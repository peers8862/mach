# mach command reference

Generated from the command headers by `mach help --markdown` (mach 1.3.0). Do not edit by hand.

Global options go before the command: `--json`, `--dry-run`, `--host H`, `--version`, `--help`.
Exit codes: 0 OK, 1 warnings, 2 failure, 3 waiting for approval. Administrative changes preview first and act with `--apply`; subsystem sends execute immediately.

## mach ai

Preview/apply wiring of shared AI rules and skills into each tool (plan 06)

```text
mach ai apply [rules|skills] [--tool T] [--apply]
mach ai show  [rules|skills] [--tool T]        (same preview, never writes)
```

```text
Tools: claude, codex, cursor-agent (Cursor), kiro, grokcli-agent. For each tool it shows what is wanted, what exists,
and the state: ok | create | refresh | differs (not safe to touch) | blocked (a source is missing) | manual.
rules: claude = ~/.claude/CLAUDE.md + CLAUDE.machine.md import stubs; codex = ~/.codex/AGENTS.md (generated);
cursor-agent = ~/.cursor/plugins/local/machine-flows/ (generated rule); kiro = ~/.kiro/steering/AGENTS.md (generated).
Generated files = ai-authored/AGENTS.md + claude/machines/<host>.md (+ codex/extra.md), with a "generated by mach" header.
skills: ai-authored/skills/<name>/ -> symlinks ~/.claude/skills/<n> and ~/.agents/skills/<n> (codex, cursor-agent; links point
from the tool folder INTO machine-flows, never inside it); kiro gets copies. Existing paths are never replaced.
--apply does only safe writes: create missing stubs/links/copies, refresh files that mach itself generated (with a
backup + rollback line). A file with other content (e.g. a hand-written ~/.claude/CLAUDE.md) is "differs": preview-only.
Not automated (manual, shown as such): Cursor account User Rules, Grok Bot private skill, credential/settings JSON.
```

## mach docs

Update the per-machine docs-index CSVs (collect) or rebuild the xlsx workbook (build)

```text
mach docs [collect] [--apply]
mach docs build [--apply]
mach docs macstat [--apply]
```

```text
collect (default): runs the copied collector (libexec/mach-docs-collect.py, from staging/docs-index/collect.py)
into a temp folder and shows which rows would be added, removed or changed in inventory/<host>/docs-index.csv.
--apply writes the CSVs (after a backup and a rollback line). Collection runs on one machine only (single writer): [machines] collector, default this machine.
State (births-seen.json, mac-stat.tsv) lives OUTSIDE machine-flows: ~/machine-flows-staging/docs-index/ (MACH_STATE_DIR).
build: wraps scripts/docs-index-build.py. Plan 00 rule 10: the workbook is rebuilt ONLY when you run this explicitly.
Preview builds into a temp file and reports the size; --apply replaces inventory/docs-index.xlsx (the script backs up the old one).
macstat (Mac): runs the light stat gathering (mac-stat.sh) and, with --apply, saves mac-stat.tsv into the state folder for the collector machine.
Personal history (purposes, dates, extra rows) comes from a gitignored docs-history.local.py ($MACH_DOCS_HISTORY, then
$MACH_CONFIG_DIR, service-settings/mach/, config/); without one only the generic walk runs. Format: config/docs-history.example.py.
Override the collector with MACH_DOCS_COLLECT (tests).
```

## mach doctor

Read-only health checks for this machine (Syncthing, services, CLI names, Grok Bot, disk, hygiene, caps)

```text
mach doctor [--json] [--quiet]
```

```text
Prints one line per check: OK|WARN|FAIL|INFO  <check>  <detail>, then a summary. Exit code: 0 all OK/INFO,
1 any WARN, 2 any FAIL. Read-only: it changes nothing and prints no secrets (the Syncthing API key is used from
memory only; Grok Bot credential files are never opened). Every external call has a timeout; the run stays under ~15 s.
--quiet prints only WARN/FAIL lines and the summary. --json prints {host, checks[], summary, exit}.
Config: [doctor] in service-settings/mach/config.toml (thresholds, peer_ssh, syncthing_url).
```

## mach inventory

Regenerate inventory/`<host>`/ for this machine, show the diff, write only with --apply

```text
mach inventory [--host H] [--section S] [--light|--full] [--diff] [--apply]
```

```text
Runs scripts/inventory-linux.sh (or inventory-macos.sh) into a temp folder under the staging area, then compares
it with ~/machine-flows/inventory/<host>/ file by file. Nothing is written without --apply (or an interactive y).
--host must be the current host: inventories are generated on the machine they describe.
--section S limits the comparison to files whose name starts with or contains S (e.g. 70, services, raw).
Linux runs the full generator (home-folder sizes with du, network tests; slow on a spinning disk). macOS runs light by default
(SKIP_SIZES=1 SKIP_NET=1 SKIP_BREW_DOCTOR=1: no heavy scans on the Mac). --light / --full force one or the other. A light run
replaces the sizes table with a "skipped" note when applied, so use --full when you want the sizes refreshed.
--diff shows the whole diff per file instead of the first lines. The hand-maintained 75/76 files and docs-index.csv
are never touched, and the generated inventory/README.md is not copied (it would drop the other machine's notes).
--apply backs the replaced files up to ~/machine-flows-staging/backups/<ts>-mach-inventory/ and prints a rollback line.
Afterwards run `mach docs` (preview) so the docs index records the new modified dates.
```

## mach mcp

Render (dry-run) or apply the MCP server manifest for each tool via scripts/mcp-apply.sh

```text
mach mcp [render] [--tool T]
mach mcp apply [--tool T] [--apply]
```

```text
Tools: claude, codex, cursor-agent, kiro (also grokbot, the account-level Grok Bot notes). Default: all tools.
render prints what scripts/mcp-apply.sh would change (its dry-run) and changes nothing.
apply shows that preview first and passes --apply through only when you give --apply (or answer y on a tty).
NOTE: mcp-apply.sh --apply is currently a documented stub that exits 3 without changing anything; mach reports it
as "not implemented yet" (exit 1) instead of pretending it applied. grokcli-agent has no MCP target in mcp-apply.sh.
Source of truth: ~/machine-flows/mcp/servers.yaml. Secrets are never printed (variable names only).
```

## mach memory

Set up and review lessons (init skeleton, duplicates, stale, caps); collect/promote are preview-only in v1

```text
mach memory init [--reindex] [--apply] [--json]
mach memory review [--save] [--apply] [--json]
mach memory collect          (PREVIEW-ONLY in v1: lists raw memory files it would turn into proposed lessons)
mach memory promote          (PREVIEW-ONLY in v1: lists promotion candidates for AGENTS.md; changes nothing)
```

```text
init previews, and with --apply creates the plan 09 skeleton under service-memories/lessons/ without overwriting anything
that exists: README.md (frontmatter template + writing rules), INDEX.md (generated from lesson frontmatter), the starter topic
folders and archived/INDEX.md. The existing reviews/ folder is left alone. Backup + rollback line; rollback removes only what
init created. --reindex regenerates INDEX.md from the lessons' frontmatter (backs up the old one first).
review scans service-memories/lessons/**/*.md (plan 09 schema: id, title, date, source, scope, confidence, review_by,
status ...) and reports: missing fields, stale (review_by past), duplicate candidates (title/slug similarity),
contradiction CANDIDATES (similar titles, opposite advice words), proposed backlog, promotion candidates and cap breaches
(index 300 lines, proposed 30, 40 per topic, 300 live, ~40 lines per lesson, AGENTS.md 130/150). Report goes to stdout;
--save also writes it to <machine-flows>/service-memories/lessons/reviews/YYYY-MM.md (plan 09 section 7). The folder is
created if missing, with a short README.md saying what the files are. An existing file for the month is never overwritten:
the next save becomes YYYY-MM-2.md, then -3 and so on. Override the folder with [memory] reviews_dir or MACH_REVIEWS_DIR.
--apply moves lessons already marked superseded/archived (or low-confidence and 90+ days past review_by) into
lessons/archived/<topic>/ with status: archived, backs up first, removes their INDEX.md lines and prints a rollback line.
If INDEX.md is a generated one (it carries the "generated by mach" marker) --apply regenerates it after archiving.
A missing lessons folder or INDEX.md is INFO, not a warning: fix it with `mach memory init --apply`. The legacy ~/machine-flows/files/Lessons is noted but not touched
(migration is `mach memory migrate`, a later step). collect and promote never write anything in v1.
```

## mach names

Check that CLI agent names are explicit (cursor-agent, grokcli-agent, no bare `agent`)

```text
mach names [--fix] [--apply]
```

```text
Report mode (default): looks for a bare `agent` in ~/.local/bin, ~/.grok/bin and /usr/local/bin, checks that
cursor-agent (and grokcli-agent when grok is installed) exist, and that `agent` is not on PATH. Exit 1 on problems.
--fix previews what it would do: remove bare `agent` SYMLINKS in the two user bin dirs (targets recorded in
~/machine-flows-staging/backups/<ts>-mach-names/removed-links.tsv) and create grokcli-agent -> ~/.grok/bin/grok if missing.
It acts only with --apply (or an interactive y). /usr/local/bin is never touched. Never runs any CLI, never uses sudo.
After any Cursor or grok install or update the vendor installers recreate `agent`: run `mach names --fix --apply`.
Test/relocation knob: MACH_BIN_DIR replaces ~/.local/bin.
```

## mach onboard

Checklist for a new machine: prerequisites, link mach, Syncthing pairing, then previews

```text
mach onboard [--apply] [--skip-previews]
```

```text
Checks prerequisites (bash, python3 >= 3.9, git; syncthing and tmux), that ~/.local/bin is on PATH, and whether mach
is linked. Prints the Syncthing pairing steps (text only: mach never touches Syncthing). Then runs, in PREVIEW mode:
mach inventory, mach names, mach ai apply, mach mcp render (--skip-previews skips them; inventory can take a while).
--apply performs ONE change: it runs install.sh --apply to link ~/.local/bin/mach -> <this checkout>/bin/mach.
Exit codes: 0 all prerequisites met, 1 something optional/missing, 2 a hard prerequisite is missing.
```

## mach plans

List plans with open/total checkbox counts; archive a finished plan (plans/README.md section 4)

```text
mach plans list [--json]
mach plans archive <NN|file> [--apply] [--force]
```

```text
list shows each plans/NN-*.md with its Status line and open/total `- [ ]` boxes. Plans with every box ticked are
marked "archive candidate" (the user's OK is still required: agents never archive on their own judgment).
archive previews, then (only with --apply) performs the README section 4 steps: set the Status line to
"done YYYY-MM-DD, archived"; mv the file to plans/archived/; fix references (plans/NN-name.md -> plans/archived/NN-name.md,
other hits are listed for you); add the plan 00 Change log line; update the register row in plans/README.md.
The docs-index step is printed, not run: mach docs --apply. Plan 00 is never archived. Open boxes need --force.
Everything it edits is backed up first; a one-line rollback is printed.
```

## mach services

Compare live login/boot services and scheduled jobs with the 75/76 index files

```text
mach services [check]            (default: compare live units with the index files)
mach services show               (print the rows parsed from 75 and 76 for this host)
mach services [check] --update   (print a PROPOSED patch for the index files; v1 never writes them)
```

```text
Reads inventory/<host>/75-custom-startup-services.md (login/boot) and 76-custom-scheduled-jobs.md (scheduled).
Live side, Linux: custom systemd user units/timers in ~/.config/systemd/user, XDG autostart entries, `crontab -l`,
and `systemctl --user --failed`. Live side, macOS: ~/Library/LaunchAgents plists, `launchctl print`, `crontab -l`.
Reports OK, MISSING (an active row has no live counterpart), UNLISTED (live item not in the index) and FAILED.
--update (v1): prints the table rows to add and the rows to re-check as a proposed patch. Nothing is written;
edit the 75/76 file yourself or ask an agent (plan 00 rules 8 and 14). Exit 1 when anything needs attention.
```

## mach sheets

Sheet sets: lint, build (CSVs -> xlsx), scaffold and refresh a folder of index.csv + CSV files + a generated workbook

```text
mach sheets lint <dir> [--json]
mach sheets build <dir> [--dry-run] [--json]
mach sheets new <dir> [--apply]
mach sheets refresh <set> [--build] [--check] [--dry-run] [--out DIR]
```

```text
A sheet set is a folder with index.csv (columns: id, file, sheet_name, title, description, owner, source, generated_by,
updated, rows), the CSV files it lists and <name>.xlsx, a workbook generated from them (Index sheet first, then one sheet
per CSV, frozen bold header, autofilter). The CSVs are the source of truth; edit them, never the workbook.
lint checks the set (every CSV indexed, every listed file there, rows and updated right, sheet names unique and at most 31
characters, Excel-safe cells, workbook current); exit 0 OK, 1 warnings, 2 failures.
build is the explicit action, so it writes: it fixes rows/updated in index.csv, then writes the workbook (backups first;
--dry-run only reports). The workbook is reproducible (same input, same bytes) and needs no install (no openpyxl).
new previews, then (--apply) scaffolds an empty set: index.csv with the header row plus a README.md.
refresh mach regenerates the CSVs of docs/sheets and docs/COMMANDS-TABLE.md from the code and headers (then run build);
the set name `mach` is the only generated set. --check is the drift check used by the tests.
```

## mach approve

Approve a run that is waiting at a gate and continue it

```text
mach approve <id> [--step N] [--json]
```

```text
<id> may be a unique prefix. Only runs with status waiting-approval can be approved.
Flows continue from the gate step (--step N must match the pending gate). Prompt runs continue past
their before-run / apply / outward gate. An approved outward step still only writes a handoff file.
Agent output is saved in the run folder transcript.txt; approval prints a short status and transcript path.
Exit codes follow the run: 0 done, 2 failure, 3 if the run reaches another gate.
```

## mach ask

Send a prompt straight to one named tool in headless mode (read-only by default)

```text
mach ask <tool> "<prompt>" [--write] [--path P] [--dry-run] [--json]
```

```text
Tools (explicit names only): claude, codex, cursor-agent, grokcli-agent, kiro (runs kiro-cli), grokbot.
There is no bare `agent` command. The answer goes to stdout and to a run record in files/runs/.
grokbot has no CLI: mach writes a paste-ready prompt file and a queued run item (nothing is automated).
Headless flags (checked with each CLI's --help): claude -p --permission-mode plan; codex exec --sandbox read-only;
cursor-agent -p --mode ask; kiro-cli chat --no-interactive --trust-tools=; grokcli-agent -p (best guess, see docs/DECISIONS.md).
--dry-run prints the exact command with the prompt truncated and runs nothing. A missing tool exits 2.
```

## mach do

Route a one-line task to the right tool and machine, confirm, run it, record it

```text
mach do "<task>" [--tool T] [--machine M] [--path P] [--write] [--bg] [--yes] [--dry-run] [--json]
```

```text
Shows the route (tool, machine, path, permission, output), asks to confirm (--yes skips), runs the tool
headless and records a run in files/runs/. Tools run read-only unless --write (or routes.permission = "write").
Routing: --tool/--machine/--path > [routes.project.<id>] in the config > routes.default_tool (claude) on this machine.
--machine other than this one: v1 creates a queued run for that machine (no SSH execution yet).
--bg runs the task inside a tmux session (error if tmux is missing).
--dry-run prints the exact command (prompt truncated) and writes nothing.
```

## mach flow

Run a multi-step recipe (flow) with approval gates

```text
mach flow <name> [input...] [--dry-run] [--queue] [--write] [--json]
mach flow list
```

```text
Recipes are Markdown files with numbered steps. Searched in ~/machine-flows/autoflows/mach/<name>.md first,
then the built-in flows/ folder (morning, research-to-plan, issue-to-pr).
Step keys: tool, machine, prompt, cmd (a mach command), handoff, output; `gate:` marks an approval stop (after that step).
A gate pauses the run: status waiting-approval, exit 3. Continue with `mach approve <id>`, stop with `mach reject <id> "why"`.
Outward steps (PR, Linear, posting) are NEVER executed by mach in v1: they produce a ready-to-run command or draft
file in the run folder and the step is marked "handoff". The input is read from the arguments, or stdin when it is "-".
--dry-run lists the steps and the exact tool commands (prompts truncated) and writes nothing.
```

## mach inbox

Bring tagged Drafts from the Mac into the synced mach inbox

```text
mach inbox pull-drafts [--apply] [--json] [--limit N]
```

```text
On macOS, reads Drafts tagged mach-outbox; validates briefs or wraps plain notes for read-only triage.
Preview shows titles and destinations. --apply writes each document once, then archives its Drafts copy.
A failed archive can be retried safely: the same Drafts UUID maps to the same inbox file.
Invalid or changed drafts stay in Drafts for correction; pickup itself does not run an AI task.
```

## mach note

Quick capture to inbox, Agenda, Drafts or a named destination

```text
mach note "text"                      (default destination: note.default, built-in inbox)
mach note agenda|drafts|inbox|<name> "text"
mach note --to agenda -- "text that may start with a destination name"
pbpaste | mach note drafts            (stdin when there is no text, or the text is "-")
mach note [dest] "text" [-t TITLE] [--tag X ...] [--tags a,b] [--project P] [--date D] [--flag] [--open]
                         [--file PATH] [--dry-run] [--json]
mach note flush [--apply]             (macOS: deliver outbox items to Agenda/Drafts)
```

```text
The first word is a destination only if it matches a built-in (inbox, agenda, drafts) or a configured
[note.dest.<name>]; otherwise it is part of the text. --to always wins. Nothing runs and no run record is made.
inbox appends to files/inbox/notes/YYYY-MM-DD-<host>.md (one file per machine per day).
agenda (macOS): MCP at 127.0.0.1:16106, then the agenda:// URL via `open -g`, then the outbox.
drafts (macOS): `drafts` CLI, then drafts:// URL via `open -g`, then the outbox.
On Linux, agenda and drafts always go to files/inbox/outbox/<dest>/ (synced); `mach note flush` on the Mac delivers them.
A fallback is never silent: it names the method used and exits 1. A file destination refuses paths outside machine-flows.
Options: -t/--title; --tag (repeatable); --tags a,b; --project (agenda); --date; --flag (drafts); --open (bring app forward).
--file PATH reads the text from a file. A local log (~/.local/state/mach/notes.log) records time, destination and method only.
```

## mach queue

List queued runs, runs waiting for approval, inbox prompts not yet run, and outbox items

```text
mach queue [--due today|YYYY-MM-DD] [--json]
```

```text
Sections: queued runs, waiting-approval runs, inbox prompts (files/inbox/prompts/*.md that have no run yet,
with the machine that will execute them), and outbox items (files/inbox/outbox/<dest>/, waiting for `mach note flush`).
--due filters inbox prompts by their `due:` date ("today" = the local date).
```

## mach research

Answer a question with sources (quick), or start the research-to-plan flow (deep)

```text
mach research "<question>" [--depth quick|deep] [--tool T] [--dry-run] [--json]
```


## mach run

Run a prompt document (task, research or flow brief): validate, plan, record, execute

```text
mach run <file.md> [--dry-run] [--queue] [--json] [--tool T] [--path P] [--machine M] [--write]
mach run --inbox [--dry-run] [--json]
```

```text
The frontmatter is checked against plan 08 section 3.6: unknown keys or values are an error with the line
number (exit 2). The input file is never modified; its state lives in the run record (files/runs/).
--dry-run shows the plan and the exact tool command (prompt truncated) and creates no record.
--queue creates a queued run and returns its id at once. `machine: any` queues for the background machine ([queue] background_machine, default this machine).
--inbox runs every files/inbox/prompts/*.md addressed to this machine that has not run yet.
Task/research permission: write grants tool writes, including --inbox, and forces a before-run approval gate.
Run records include pickup/approval/agent timings, actual tool, quota errors, Git sandbox warnings and transcript.txt.
approval: before-run waits at a gate first; before-apply runs the tool read-only and waits before writing the output.
output: pr or linear-comment is outward: it ALWAYS stops at a gate (exit 3) and, once approved, only writes a
ready-to-run handoff (mach never opens PRs or posts). type: flow documents are handed to `mach flow`.
Exit codes: 0 done/queued, 1 some inbox docs invalid, 2 validation or tool failure, 3 waiting for approval.
```

## mach status

Show recent runs and their state, or one run in detail

```text
mach status [id] [--status S] [-n N] [--all] [--json]
```

```text
Without an id: the most recent runs (default 15) from files/runs/. With an id (or unique prefix): that run's
frontmatter, steps table, outputs and notes. Status values: queued, running, waiting-approval, done, failed, cancelled.
Runs from every machine are listed (each machine writes only its own records; Syncthing carries them).
```

## mach subsystem

Manage subsystem manifests and send prompts to unit roles

```text
mach subsystem list|show <id>|lint [id]|new <id> [--from D] [--apply] [--replace]
mach subsystem unit|role <id> --from D [--apply]
mach <subsystem> [unit] [prompt] [--role R|--to D] [--roles] [--reply chat|inbox] [--write] [--force] [--dry-run] [--json]
```

```text
A subsystem is a keyed TOML manifest in machine-flows/subsystems/<id>/subsystem.toml.
Unit sends execute immediately. Grok Bot uses a router webhook when private secrets are safe; otherwise it queues a paste-ready prompt.
`new`, `unit` and `role` preview changes; --apply writes with a staging backup. Lint exits 2 for FAIL, 1 for WARN.
```
