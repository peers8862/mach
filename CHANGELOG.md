# Changelog

## 1.3.0 — 2026-10-08

- Public release: the tree holds no personal names, machines, paths or accounts. `~/machine-flows` stays the default root.
- Machine names are config-driven. New `[machines]` section: `names`, `mac` (the macOS machine), `collector` (where `mach docs collect`
  runs) and `[machines.match]` (hostname prefix to machine name). Without it mach uses the short hostname. The `machine:` key in prompt
  documents accepts `any` plus the configured names. `queue.background_machine` defaults to the machine you run on. Python helper
  `lib/mach_common.py` gained a tiny CLI (`host|mac|collector|names|get KEY`) that the bash scripts use.
- `mach docs macstat` takes its extra paths and crontab pattern from `[docs] macstat_paths` and `macstat_cron_pattern`.
- The Drafts hub builder (`tools/build-drafts-hub.py`) defaults to the generic name "Mach Hub" (file `Mach-Hub.draftsAction`); `--name`,
  `--templates`, `--out` and `[drafts] hub_name` / `hub_group_uuid` change it.
- Example host configs are now `config/hosts/linux-box.example.toml` and `mac-laptop.example.toml`; the docs-history example uses generic
  machine names.
- Standalone tests: templates and the subsystem scaffold used by the tests live in `tests/fixtures/`; no test reads the real
  machine-flows tree or `$HOME`. `tests/test_lint.sh` fails on such reads and on personal paths, emails, IPs and tokens in any tracked text.
- Removed `docs/BUILD-BRIEF.md` (an internal build brief). COMMANDS.md, COMMANDS-TABLE.md, `docs/sheets/` and the workbook regenerated.
## 1.2.2 — 2026-10-08

- Generic by default: `docs/sheets/subsystem-units.csv` is generated from the new `config/subsystem.example.toml` (id `demo`, units `alpha`,
  `beta`, `gamma`) and `templates.csv` from a generic list in `lib/mach_sheets_gen.py`. The generated set no longer reads anything outside
  the repo, so a clean clone sees no skipped CSVs.
- `config/config.example.toml` uses `[note.dest.work]` ("Example Project") and `[routes.project.example]` (`~/projects/example`).
- Subsystem, sheets, note and parser tests run on the example manifest and example config. Wording in README, GUIDE, DECISIONS and the sheet
  descriptions describes mach generically. Behaviour for real manifests under `~/machine-flows/subsystems/<id>/` is unchanged.

## 1.2.1 — 2026-10-08

- Generated markdown now renders in VS Code preview and other CommonMark/GFM viewers: `mach help --markdown` puts `<placeholders>` in
  code spans; `docs/COMMANDS-TABLE.md` wraps command, subcommand, usage, flag, argument and default cells in code spans (pipes escaped
  as `\|`), keeps every row at the header's column count, and stays on one line per cell.
- New `tests/test_markdown.py` parses every `.md` under `docs/` plus `README.md` and fails on column-count drift, a missing separator row,
  no blank line around a table or heading, raw `<tag>` outside backticks, indented-code usage, or an unclosed fence (with self-tests).
- Internal build-note headings got their blank lines. COMMANDS.md, COMMANDS-TABLE.md, `functions.csv` and the workbook regenerated.

## 1.2.0 — 2026-10-08

- New `mach sheets lint|build|new|refresh`: generic **sheet sets** (a folder with `index.csv`, the CSVs it lists and a generated xlsx).
  `build` writes the workbook with the standard library only (Index sheet first, frozen bold header, autofilter, column widths,
  reproducible bytes) and keeps `rows`/`updated` in `index.csv`; `lint` checks orphans, missing files, counts, sheet names, Excel-safe cells,
  and that the workbook is current; `new` scaffolds a set (preview, then `--apply`).
- First set: `docs/sheets/` (`mach.xlsx`: commands, flags, functions, config keys, destinations, templates, subsystem units), generated by
  `mach sheets refresh mach` from code and headers; also `docs/COMMANDS-TABLE.md`. A test fails when the committed files drift.
- Command headers gain `# mach-subcommands`, `# mach-status`, `# mach-writes`, `# mach-flag` (ignored by `mach help`); `DEST_DOCS` tables added
  to `mach_subsystem` and `mach_note`. Docs: README, GUIDE ("Sheet sets"), DECISIONS, COMMANDS regenerated.
- Tests: `tests/test_sheets.sh`, `tests/test_sheets.py`; `test_lint.sh` scans text files only (`grep -I`).

## 1.0.0 — 2026-10-08

First release (spec: plan 08).

- Entry script `bin/mach` (bash 3.2 compatible): global `--help`, `--version`, `--json`, `--dry-run`, `--host`; help text built from the
  header comments of each `libexec/mach-<command>` script; `mach help --markdown` generates `docs/COMMANDS.md`.
- Upkeep commands: `doctor`, `inventory`, `docs` (collect, build, macstat), `names`, `services`, `mcp`, `ai`, `memory`, `plans`, `onboard`.
- Work gateway: `do`, `ask`, `note` (inbox, Agenda, Drafts, named destinations, outbox + `note flush`), `research`, `run` (prompt
  documents, `--queue`, `--inbox`), `flow` (built-in recipes `morning`, `research-to-plan`, `issue-to-pr`), `status`, `queue`,
  `approve`, `reject`.
- Run records in `files/runs/YYYY/MM/<id>/` with statuses queued, running, waiting-approval, done, failed, cancelled; approval gates
  (exit 3); outward steps are handoffs only.
- Config: built-in defaults, `service-settings/mach/config.toml`, `hosts/<host>.toml`, unsynced `~/.config/mach/local.toml`, env, flags.
- `mach docs`: the collector (`libexec/mach-docs-collect.py`) is generic; the user's own history rows (purposes, change-log dates, rows
  for files outside machine-flows) live in a gitignored `docs-history.local.py`, found via `$MACH_DOCS_HISTORY`, `$MACH_CONFIG_DIR`,
  `service-settings/mach/` or `config/`. Format: `config/docs-history.example.py`. Without one, only the generic walk runs (one INFO line).
- Safety: every outside program (`open`, `drafts`, `osascript`, the AI CLIs, `tmux`, `launchctl`, `systemctl`, `crontab`, `ssh`) is resolved
  through an override variable (`MACH_OPEN_CMD`, `MACH_DRAFTS_CMD`, ...; `MACH_AGENDA_MCP_URL` for Agenda). Tests pin them all into the
  sandbox and put canary stand-ins for the real programs on `PATH`; a test that reaches one fails. `mach doctor` lists symlinks, secrets-guard
  matches and sync conflicts in a fixed case-insensitive order.
- Python 3.9+ stdlib only; `lib/minitoml.py` is the TOML fallback for Pythons without `tomllib`.
- `install.sh` links `bin/mach` into `~/.local/bin` (preview by default, `--apply`, `--uninstall`).
- Tests: `bash tests/run.sh` (bash + python unittest, mock tools, sandboxed), shellcheck-clean, bash 3.2 / python 3.9 lint.
- Preview-only in v1: `memory collect`, `memory promote`, `services --update`. Stub: `mcp apply` passes through to `mcp-apply.sh --apply`,
  which is itself a documented stub. Not in v1: SSH execution for `--machine`, timers, the Drafts hub action.
